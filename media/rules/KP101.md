# KP101 — Nested loops (estimated O(nᵏ))

Loops over input-sized data are nested; running time grows as a power of n.

**Category:** Performance · **Languages:** Python, JavaScript, TypeScript, Java

## Why it matters

Two nested loops over n items do n² steps: 1,000 items is a million steps, 100,000 items is ten billion. AI-generated code often reaches for the obvious nested loop where a set, dict or sort would do it in one pass. This is an estimate from the code shape — "KASAUTI: Prove Complexity" measures the real growth.

## How to fix

- Ask: is the inner loop searching for something? Build a set/dict once, then look up in O(1).
- If you compare every pair, sort first and use two pointers (O(n log n)).
- Loops over a small constant range (range(3), i < 4) are ignored by this rule.

## Before → after

```
for a in xs:
    for b in ys:
        if a == b:
            common.append(a)
```

```
ys_set = set(ys)
common = [a for a in xs if a in ys_set]   # O(n + m)
```
